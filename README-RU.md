## Обзор

Проект реализует шаблонный класс `linked_list<T>` на основе односвязного
**циклического** списка вместе со вспомогательной структурой `node<T>`. Класс
владеет динамически выделенными узлами (правило трёх), полностью копируем и
бросает исключения из `std::stdexcept` при некорректных аргументах.

Поверх класса решаются две практические задачи:

* **(базовая)** объединение двух отсортированных списков в один
  отсортированный список без дубликатов;
* **(сложная)** Ханойская башня, где каждый стержень представлен списком,
  а состояние стержней печатается в виде ASCII-башен.

Код написан в стиле **K&R** (`тип имя() {`, отступ 2 пробела, идентификаторы
в `snake_case`) и использует **возможности C++26**, документированные на
cppreference:

* **Именованные модули** — `import std;` подключает всю стандартную
  библиотеку без заголовочных файлов;
* **Контракты** — `contract_assert` (а также формы `pre` / `post` в
  деклараторе) выражают внутренние инварианты, такие как
  `tail_->next == head_` и `size_ == expected`. Ошибки, адресованные
  пользователю, по-прежнему выражаются через исключения, чтобы вызывающий
  код мог их обработать.

## Требования

Работа следует минимальным требованиям задания:

1. Компилируется без предупреждений при максимальном уровне предупреждений:
   * GCC / Clang: `-Wall -Wconversion -Wextra -Wpedantic`
   * MSVC: `/W4 /utf-8`
2. Никаких глобальных переменных (константы допустимы).
3. Все идентификаторы написаны на английском; транслит запрещён. Русский
   язык используется только в комментариях.
4. Никакого построчного комментирования — не более одного короткого
   комментария на логический блок.
5. Единый стиль именования (K&R / `snake_case`) применяется ко **всем**
   именуемым сущностям — функциям, методам, классам, переменным, параметрам,
   файлам.
6. Git-репозиторий содержит осмысленную серию коммитов с содержательными
   заголовками и корректно настроенный `.gitignore`; артефакты сборки
   никогда не коммитятся.

Дополнительные ограничения из задания:

* **Контейнеры STL не используются** нигде (`std::vector`, `std::list` и т. п.
  запрещены).
* Класс копируем и непосредственно управляет выделяемым ресурсом.
* Некорректные ситуации (`operator[]` на пустом списке, `pop_head` /
  `pop_tail` на пустом списке, …) бросают исключения из `<stdexcept>`.
* Весь ввод-вывод осуществляется исключительно через `std::cin` /
  `std::cout`.
* Решения задач расположены **вне** класса — это свободные функции в модуле
  `tasks`.

## Сборка

### С использованием CMake (рекомендуется)

```sh
cmake -G Ninja -B build -Wno-dev
cmake --build build
```

Сборка создаёт два исполняемых файла в каталоге `/build`:

| Бинарник | Назначение |
|----------|------------|
| `main`   | интерактивная программа — запускает задачу 8, затем задачу 3 |
| `tests`  | набор автоматических тестов (17 тестов); возвращает `0` при успехе |

### Напрямую через компилятор (GCC 16.1+)

```sh
g++ -std=c++26 -fmodules -fcontracts \
    -Wall -Wconversion -Wextra -Wpedantic \
    --compile-std-module \
    src/main.cpp src/tasks.cpp -o main
g++ -std=c++26 -fmodules -fcontracts \
    -Wall -Wconversion -Wextra -Wpedantic \
    --compile-std-module \
    src/test.cpp src/tasks.cpp -o tests
```

Флаг `-fcontracts` включает контрактные утверждения C++26, используемые
в `linked_list` и `tasks.cpp`.

## API `linked_list<T>`

| Метод                                           | Описание                                                              |
|-------------------------------------------------|-----------------------------------------------------------------------|
| `linked_list()`                                 | Конструктор по умолчанию — пустой список.                             |
| `linked_list(const linked_list&)`               | Конструктор копирования (глубокое копирование).                       |
| `linked_list(std::size_t, seed, min, max)`      | Конструктор со случайным заполнением (`requires std::integral<T>`).   |
| `~linked_list()`                                | Освобождает все узлы.                                                 |
| `operator=`                                     | Присваивание копированием (copy-and-swap).                            |
| `swap(linked_list&)`                            | Обмен за O(1).                                                        |
| `size()` / `empty()`                            | Запросы размера.                                                      |
| `push_tail(const T&)`                           | Добавляет один элемент в конец.                                       |
| `push_tail(const linked_list&)`                 | Добавляет другой список в конец.                                      |
| `push_head(const T&)`                           | Добавляет один элемент в начало.                                      |
| `push_head(const linked_list&)`                 | Добавляет другой список в начало.                                     |
| `pop_head()`                                    | Удаляет первый элемент; бросает исключение на пустом списке.          |
| `pop_tail()`                                    | Удаляет последний элемент; бросает исключение на пустом списке.       |
| `delete_node(const T&)`                         | Удаляет все узлы, значение которых равно аргументу.                   |
| `operator[](std::size_t)`                       | Доступ по индексу; индекс берётся **по модулю размера** (циклический список). |
| `operator[](std::size_t) const`                 | То же, только для чтения.                                             |
| `operator<<`                                    | Печатает список в `std::ostream` (используется через `std::cout`).    |

Поскольку список циклический, любой индекс приводится по модулю текущего
размера, поэтому каждый индекс даёт корректный элемент. На пустом списке
по-прежнему выбрасывается `std::out_of_range`.

## Базовая задача 8 — объединение отсортированных списков без дубликатов

```cpp
linked_list<int> merge_sorted_unique(const linked_list<int>& first,
                                     const linked_list<int>& second);
```

Оба входа предполагаются отсортированными по возрастанию. Функция выполняет
линейное **слияние двумя указателями**, пропуская равных соседей, и
возвращает новый отсортированный список, который содержит каждое
различное значение ровно один раз. Дубликаты *внутри* одного входа
также схлопываются.

Сложность: `O(n + m)` по времени, `O(n + m)` дополнительных узлов.

## Сложная задача 3 — Ханойская башня со списками

```cpp
void hanoi(unsigned int disk_count);
```

Три экземпляра `linked_list<unsigned>` представляют стержни `A`, `B`, `C`.
Диски хранятся как их размеры (большее значение = больший диск), поэтому
каждый стержень — это список, отсортированный по убыванию: самый маленький
диск всегда находится в его **голове**. Это делает допустимым ход
`pop_head` на исходном стержне + `push_head` на целевом, поскольку в
Ханойской башне может двигаться только верхний (самый маленький) диск.

Рекурсивное решение переносит `n` дисков с `A` на `C`, используя `B` как
вспомогательный стержень. После каждого хода состояние всех трёх стержней
печатается в виде ASCII-башен (например, `[3]` — диск размера 3,
`[ ]` — пустая ячейка). Поскольку стержни рисуются выровненными по низу,
диски всегда «опираются» на основание.

Рекурсивное решение выполняется за `2^n - 1` ходов.

## Используемые возможности C++26

| Возможность | Где | Назначение |
|-------------|-----|------------|
| **Именованные модули** (`import std;`) | `linked_list.cppm`, `tasks.cppm`, `tasks.cpp`, `main.cpp`, `test.cpp` | Более быстрая и чистая компиляция без заголовочных файлов препроцессора. |
| **Контракты** (`contract_assert`) | методы-члены `linked_list` | Проверка внутренних инвариантов (`tail_->next == head_`, `size_ == other.size_`, …) в debug-сборках. |
| **`requires`-выражения** | `linked_list(count, seed, min, max)` | Ограничение конструктора случайного заполнения целочисленными типами. |
| **Модули стандартной библиотеки** | `import std;` | Вся стандартная библиотека доступна без `#include`. |

> **Примечание:** сопоставление с образцом (pattern matching) **не** вошло
> в C++26; оно отложено до C++29. Поэтому проект не использует `std::match`.

## Устройство модулей (почему `tasks.cppm` + `tasks.cpp`?)

Модуль `tasks` разделён на **интерфейсный блок модуля** (`tasks.cppm`, в
котором объявлены две экспортируемые функции) и **реализационный блок
модуля** (`tasks.cpp`, в котором определены их тела). Это эквивалент
разделения заголовка и `.cpp` в эпоху модулей:

* Изменение тела `hanoi` или `merge_sorted_unique` вызывает перекомпиляцию
  только `tasks.cpp`, **но не** `main.cpp` и `test.cpp`.
* Локальные вспомогательные функции (`print_disk_field`, `print_rod_cell`,
  `print_state`, `hanoi_recursive`) находятся в `tasks.cpp` как `static`-
  функции и невидимы для пользователей модуля.

Модуль `linked_list` **не** разделён так же, потому что это шаблон — его
полное определение должно быть видно каждой единице трансляции, которая его
инстанциирует, поэтому всё хранится в `linked_list.cppm`.

## Стиль кодирования

Стиль K&R / «ядерный» стиль Linux:

* Классы, структуры, функции, переменные, параметры, файлы: `snake_case`
  (`linked_list`, `node`, `push_tail`, `merge_sorted_unique`).
* **Возвращаемый тип и имя функции на одной строке**, открывающая скобка на
  той же строке:

  ```cpp
  int main() {
    ...
  }
  ```

* Отступ 2 пробела.
* `nullptr` вместо `NULL`, `static_cast<>` вместо C-приведений.
* Без пробела между именем функции и `(`.

Стиль применяется единообразно ко всем именуемым сущностям в проекте.
